# Weatherie Landing

This repo contains the Astro landing site for Weatherie.

It is a static marketing site with:
- the main landing page in `src/pages/index.astro`
- a locally embedded Flutter demo served from `public/demo`
- a build script that regenerates that demo from the sibling Flutter app

## Local Development

From `landing/`:

```sh
npm install
npm run dev
```

Astro runs at `http://localhost:4321`.

For live weather in the embedded Flutter previews, create `landing/.env` from `.env.example`:

```sh
cp .env.example .env
```

Set:

```env
OPENWEATHERMAP_API_KEY=your_key_here
```

Then restart the Astro dev server or rebuild the site so the key is embedded into the demo iframe URLs at build time.

For Vercel or any other static deployment, set the same `OPENWEATHERMAP_API_KEY` environment variable for the landing build. The Flutter preview reads the key from the iframe URL generated by Astro, so the value must exist when the landing site is built.

## Flutter Demo Workflow

The landing page embeds a generated Flutter web demo. That demo is not source-authored in this repo; it is built from the sibling Flutter project at `../weatherie` (override with `APP_DIR=...`).

The demo entrypoint is the app's `lib/main_demo.dart`. It boots against mock
weather data and the bundled **Open Road** theme, so it needs no backend and no
location permission — a first-time visitor sees a full, themed forecast
immediately. If `OPENWEATHERMAP_API_KEY` is set the page upgrades it to live
weather for the visitor's approximate location, and silently stays on the mock
data if that fails.

To rebuild and sync the demo bundle:

```sh
npm run build:demo
```

That runs:
- `../weatherie/scripts/build_demo_web.sh --base-href /demo/`
- `rsync` into `public/demo/`

The app-side build script trims the bundle (`scripts/trim_demo_web_bundle.sh`):
it keeps only the two Open Road images the demo actually paints, and strips the
`theme_thumbs/soon/` glimpses plus any thumb for a theme that is not live in
`/v1/catalog`. **That strip is load-bearing — this repo is public, and those
filenames would otherwise disclose unannounced theme names.** Re-check it if the
bundle layout ever changes.

## Build Commands

```sh
npm run build
```

Builds only the Astro site.

```sh
npm run build:deploy
```

Builds the Flutter demo first, then builds the Astro site.

Use `build:deploy` for production output when the embedded demo has changed.

## Repo Notes

- `public/demo/` is generated from the sibling Flutter repo.
- If this landing repo is deployed by itself on Vercel, `public/demo/` must be present in the repo or the `/demo/...` embeds will 404.
- This repo expects the Flutter app repo to exist at `../weatherie` if you use `build:demo` or `build:deploy`.
- The landing page uses one full app preview plus a generated hourly demo scene from Flutter.

## Media on the landing page

- `public/press/` is generated by the app repo's `tools/media_harness/press.py`.
  The landing page **reuses** its already web-sized theme stills
  (`/press/media/themes/<id>.jpg`, 416×746) rather than duplicating them, which
  keeps this repo from growing every time the page changes.
- `public/media/` holds the few landing-owned derivatives (~480 KB total):
  web-sized store plates and the video poster. Regenerate them from
  `public/press/media/` masters rather than committing new masters here — the
  repo is already large and the owner has flagged its size.
- Only **published** themes may appear on the page. The catalogue block in
  `src/pages/index.astro` is a literal list; re-check it against
  `GET /v1/catalog` before adding to it, and never list a draft.

## Store links

`src/pages/index.astro` has a `STORE_LINKS` constant at the top. While both
strings are empty the download section renders a "coming soon" note instead of
buttons, so nothing ever links to a 404. Fill in the two URLs when the listings
go live and the buttons appear — no other edit needed. They are deliberately
plain text buttons, not reproductions of Apple's or Google's badge artwork,
whose brand guidelines constrain how the official badges may be drawn.
